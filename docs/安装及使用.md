# 安装及使用

本系统采用B/S架构，支持在线访问与本地部署两种使用方式。为兼顾快速体验与研究增强展示，系统提供标准版和增强版两种本地部署模式。

## 1 安装环境要求

系统对部署环境提出如下最低配置要求。标准版需处理器四核x86_64架构，内存不少于8GB，硬盘可用空间不少于50GB，网络带宽不低于2Mbps。软件方面，走容器方式时宿主只需 Docker（含 compose）——Python 3.12 与 FFmpeg 都在镜像内自带，不用在宿主安装；只有准备增强版模型那一步（见 3.2）仍需宿主有 Python 3.12。浏览器推荐Chrome 90或Edge 90及以上版本以支持WebRTC。外部服务依赖DeepSeek API完成大模型分析，依赖阿里云NLS完成实时语音转写。

增强版在标准版基础上额外要求GPU环境，推荐使用NVIDIA RTX 3060及以上显卡（12GB显存），并已正确安装CUDA 11.7及以上版本。增强版需额外部署pyannote说话人分离模型、WeSpeaker声纹识别模型、TalkNet-ASD音视频同步检测模型、InsightFace人脸识别模型、CLIP ViT-B/16跨模态基座模型以及BGE-M3文本语义向量模型。仅当增强模型全部就绪时，系统才会进入真正的增强版运行路径。

## 2 在线访问

系统已部署于演示服务器，用户可通过浏览器直接访问，无需额外安装客户端软件。使用时打开浏览器输入系统访问地址进入首页，首次使用需注册账号并选择角色（教师或学生）后完成登录。教师登录后可创建课堂，输入课程主题与参考资料，系统自动生成教学设计与学习目标并分配课堂码。学生输入课堂码加入课堂，浏览器请求摄像头与麦克风权限后即可进入讨论界面。课堂过程中系统自动运行语音转写、情绪分析、发言评分、知识图谱构建等功能。课堂结束后系统自动生成学习报告与个性化习题，可在历史课堂中查看与导出。

使用在线访问方式需注意首次进入课堂时允许浏览器摄像头和麦克风权限，推荐使用Chrome浏览器以获得最佳兼容性。如通过域名或局域网地址访问，建议启用HTTPS以满足浏览器安全策略。

## 3 本地部署

本地部署分为标准版和增强版两种模式。标准版用于低门槛演示，保留系统核心流程，不要求额外部署研究增强模型，默认使用云端DeepSeek与阿里云NLS服务完成大模型分析和实时语音转写。增强版用于展示更高精度的身份绑定与多模态研究算法能力，需要额外部署开源模型与增强依赖，建议使用具备独立GPU的服务器环境。

两种模式都走**容器方式**：宿主只需 Docker（含 compose），Python 依赖、数据库、FFmpeg 都由镜像提供，不需要手工安装。

### 3.1 标准版

**第一步，备好两份配置。** 在项目根目录执行：

```bash
cp .env.example .env              # 共享密钥，至少把 LLM_API_KEY 填上
cp .env.dev.example .env.dev      # 库指向，照抄即可，不用改
```

`.env` 里至少要配这些（其余键都有默认值）：

| 键 | 填什么 |
|---|---|
| `LLM_API_KEY` | DeepSeek API 密钥。**不可为空**——为空时应用启动即抛异常 |
| `LLM_PROVIDER` / `LLM_MODEL` / `LLM_BASE_URL` | `deepseek` / `deepseek-chat` / `https://api.deepseek.com` |
| `ALIYUN_ACCESS_KEY_ID` / `ALIYUN_ACCESS_KEY_SECRET` | 阿里云 AccessKey，实时语音转写用 |
| `ALIYUN_APP_KEY` | 阿里云 NLS 应用的 AppKey |
| `RESEARCH_DEPLOYMENT_PROFILE` / `RESEARCH_MODULES_ENABLED` / `RESEARCH_RUNTIME_MODE` | 标准版填 `standard` / `false` / `documented_only` |

`.env.dev` 装的是**库指向**：六个库键（`DATABASE_URL` 与 `DB_*`）指向 compose 网络里的 `db` 服务，从模板复制即可。数据库指向**按环境分层**，线上另有 `.env.prod`，由 `APP_ENV` 选择——本机开发用不到它。

**第二步，起服务。**

```bash
docker compose up --build
```

`db`（SQL Server 2022）与 `db-init`（执行 `db/schema.sql` 建库）依次完成、`app` 就绪后，浏览器打开 <http://localhost:8000>。库表由 `db/schema.sql` 自动建立，该脚本生产开发通用且可重复执行；`storage/` 下那几个目录由应用启动时自建，不需要手工准备。

进容器查数据、看日志、在容器里跑测试的常用命令，以及"容器内跑测试会有 1 条既知基线失败"这类细节，见 `deploy/docker.md`。

**改用本地大模型（可选）**：安装 Ollama 后 `ollama pull gemma4:e4b` 拉取模型、`ollama serve` 启动服务，再把 `.env` 里的 `LLM_PROVIDER` 改为 `ollama`、`LLM_MODEL` 改为 `gemma4:e4b`、`LLM_BASE_URL` 改为 `http://127.0.0.1:11434/v1`。**容器方式下这个地址要指向宿主**——容器里的 `127.0.0.1` 是它自己：Windows / macOS 的 Docker Desktop 写 `http://host.docker.internal:11434/v1`，Linux 还要给 compose 加 `extra_hosts: ["host.docker.internal:host-gateway"]`。该步骤只替换大模型推理通道，标准版实时语音转写默认仍使用阿里云NLS。

### 3.2 增强版

增强版在标准版的基础上多配三行：把 `.env` 里的 `RESEARCH_DEPLOYMENT_PROFILE` 改为 `enhanced`、`RESEARCH_MODULES_ENABLED` 改为 `true`、`RESEARCH_RUNTIME_MODE` 改为 `enhanced_strict`。

模型要先落到 `storage/research_models/` 的六个槽位（pyannote、wespeaker、talknet_asd、insightface、clip_vit_b16、bge_m3）。仓库根提供了四个工具，按网络条件择一：

| 工具 | 用途 |
|---|---|
| `prepare_enhanced_model_layout.ps1` | 只建目录骨架，模型文件你自己放进去 |
| `install_enhanced_models_from_local.ps1` | 从本地已有的模型文件安装到各槽位 |
| `download_enhanced_open_models.py` | 从 HuggingFace 等源头下载（Python 脚本，跨平台） |
| `setup_enhanced_runtime.ps1` | 一步到位：建目录 + 装增强依赖 + 下载模型 |

这四个工具跑在**宿主**上（它们只准备模型文件，不启动服务），所以增强版这一步仍需要宿主有 Python 3.12。

> ⚠️ 增强版需要 GPU，而 `docker-compose.yml` 目前**没有**给 `app` 配 GPU 直通，
> 所以「增强版在容器里能否用上 GPU」尚未验证。见 `docs/待验收事项.md` A41。

## 4 典型使用流程

教师端使用流程包括登录系统、创建课堂、开始课堂、课堂监控、主动干预、查看投票和结束课堂七个步骤。教师使用教师账号登录后输入课程主题与参考资料创建课堂，系统自动生成教学设计与学习目标并分配课堂码。教师将课堂码分享给学生后进入实时监控看板，查看成员实时打分、发言占比、情绪波动曲线与成员交互关系图。根据系统预警（冷场、参与失衡、情绪异常）进行引导，学生触发观点投票后教师端可实时查看投票进度和结果。课堂结束后系统自动生成学习报告、知识图谱、学生个体报告。

学生端使用流程包括加入课堂、设备检测、参与讨论、查看反馈、触发投票和查看报告六个步骤。学生使用学生账号登录后输入课堂码加入课堂，允许浏览器访问摄像头和麦克风并确认设备正常。参与讨论时查看实时字幕、学习目标面板与实时对话列表，发言后3秒内收到AI评分、情绪标签和改进建议。学生可主动点击观点投票按钮，系统自动分析当前讨论内容并弹出投票弹窗展示3至5个主要观点，选择支持的观点后实时提交投票。课堂结束后查看个人学习报告，完成个性化习题，导出PDF。

AI导师使用流程包括进入AI导师、提问和查看回答三个步骤。学生在学生端界面点击AI导师按钮进入一对一辅导界面，在输入框中输入问题后点击发送，AI导师实时流式输出回答并支持多轮对话。

## 5 注意事项与建议配置

本地电脑建议默认使用标准版以保证开箱即用和较低硬件门槛。团队展示高精度身份绑定与研究算法能力时使用GPU服务器运行增强版。若通过非localhost地址访问系统并需要调用摄像头或麦克风，建议启用HTTPS与反向代理。

性能优化方面，标准版单台服务器建议不超过50个并发用户，LLM服务自动缓存1000条结果且过期时间为1小时，需确保数据库复合索引(meeting_id, user_id)已创建，前端自动压缩视频为720p以降低带宽占用。

安全配置方面，若部署于公网服务器建议启用HTTPS协议并通过Nginx进行反向代理。所有系统参数与模型配置均集中于.env文件管理，便于统一修改与跨环境迁移。系统日志与调度信息具备完整记录与回放功能，适用于比赛展示、系统演示与实地部署等多种使用场景。
